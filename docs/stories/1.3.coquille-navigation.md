# Story 1.3: Coquille d'application et navigation

## Status
Review

## Story
**As a** utilisateur mobile,
**I want** une navigation au pouce entre les grandes sections,
**so that** je circule dans l'app d'une seule main.

## Acceptance Criteria
1. Une barre d'onglets basse donne accès à Carte, Fil et Compte, avec un bouton central « Signaler » mis en avant. Toutes les cibles font au moins 44 px.
2. Les routes sont définies, et la carte comme l'admin sont **chargées à la demande** (le budget de bundle reste vert).
3. Les zones sûres iOS (encoche, barre d'accueil) sont respectées en mode installé.
4. Une page 404 et un écran d'erreur générique sont conçus avec le ton de l'app. Les erreurs JS non gérées sont journalisées en base (RPC `log_client_error`, limitée en fréquence), sans aucun service tiers.
5. Le mode sombre suit automatiquement le système.

## Tasks / Subtasks
- [x] T1 — Client Supabase unique (`src/lib/supabase.ts`), créé seulement si l'URL et la clé sont configurées
- [x] T2 — Journal d'erreurs client (`src/lib/errorLogger.ts`) : `window.onerror`, `unhandledrejection` et erreurs de route ; limite de 5 envois par minute ; messages tronqués ; **aucun effet si la RPC n'existe pas encore** (elle est créée en story 1.5) (AC 4)
- [x] T3 — `AppShell` : barre d'onglets basse en mobile (Carte, Fil, Signaler central, Compte), rail vertical à partir de 1024 px, libellés toujours visibles, `aria-current`, un tap sur l'onglet actif remonte en haut (AC 1)
- [x] T4 — Routes paresseuses (lazy) : `/` (Carte), `/fil`, `/signaler`, `/compte`. Pages provisoires sous forme d'états vides avec du ton, et action (AC 2)
- [x] T5 — Zones sûres : `env(safe-area-inset-*)` sur la barre d'onglets et l'en-tête ; le contenu est réservé au-dessus de la barre (AC 3)
- [x] T6 — `errorElement` de route : écran « Le radar a pris un coup » avec rechargement ; 404 conservée (AC 4)
- [x] T7 — Tests : barre d'onglets (liens, `aria-current`), écran d'erreur, limitation du journal d'erreurs
